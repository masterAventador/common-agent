# 北极星计划工作流设计与运行手册

> 文档编号 NP-FLOW-2027-05，正式版 1.6。本文是虚构的工作流检索测试资料。

## 设计目标

工作流用于把可重复步骤连接成可审计的执行图。它与数字员工相互独立：用户可以从工作流页面手动
启动，数字员工也可以在获得授权后调用。任何入口最终都必须进入同一个服务端校验、编译、任务队列
和运行记录链路，不能为页面演示另写一套进程内执行器。

最小工作流从开始节点进入，在结束节点收敛。开始和结束之间可以使用知识检索、AI 对话和确定性
处理节点。保存前服务端检查节点 ID、端口、连线、不可达节点和环路；页面显示连线成功不代表定义
一定合法。

## AI 对话节点的两种目标

AI 对话节点只能在“数字员工”和“平台模型”中二选一。选择数字员工时，运行读取该员工当前系统
提示、绑定知识库、获准工作流和默认模型；选择平台模型时，只获得节点输入和通用系统约束，不自动
继承任何员工知识或工具。两种目标都只能引用当前租户资源。

选择员工适合需要固定角色、业务知识和工具权限的步骤，例如让“门店制度助手”解释规则。直接选择
模型适合翻译、格式转换和无业务知识的摘要。不能同时选择员工和模型再让运行时猜优先级；保存时
发现两个字段都有值或都为空都要返回明确校验错误。

模型在模型管理中停用后，已有运行摘要仍显示实际模型，但新运行不能继续使用。员工默认模型变更后，
下一次运行采用新模型；已经开始的运行使用启动时快照，避免同一次运行中途切换模型。

## 输入、输出与变量

开始节点定义运行输入。节点只能读取显式上游输出和允许的运行上下文，不得从浏览器本地状态获取
隐藏参数。知识检索节点输出片段、引用和检索状态；AI 节点输出文本及实际目标；结束节点把允许公开
的字段组成最终结果。

变量名称使用小写字母、数字和下划线，不能覆盖保留的 run_id、tenant_id 和 actor_id。用户输入在
进入提示词前做长度检查，但不能简单删除所有特殊字符。输出超限时节点失败并给出可恢复错误，不把
截断内容伪装成完整成功。

## 运行、重试与停止

API 接受运行后原子写入 MySQL 持久任务，由独立 Worker 领取。任务可能至少投递一次，因此产生
外部副作用的节点必须使用幂等键。Worker 取得租约后仍需确认停止状态；租约丢失的实例不能继续写入
业务终态。

临时网络错误可以按有限退避重试，输入非法、权限不足和模型被停用不应自动重试。重试保留前一次
失败记录并产生新尝试，不覆盖审计证据。用户停止后，尚未开始的节点不再执行；正在调用的外部请求
尽力取消，晚到成功结果不能把 stopped 改回 completed。

## 发布与变更

草稿可以反复编辑，但只有通过校验的定义才能保存。生产使用已保存版本；页面上未保存的节点移动、
模型切换或提示词修改不能影响正在运行的版本。重大变更先复制为新版本验证，再切换默认，不在原
版本上边运行边修改。

能写业务数据的工作流必须标记高风险，由业务负责人和安全负责人批准。数字员工只有在 allowed
workflow 列表中包含该工作流时才能调用；用户手动启动仍要检查用户角色。模型本身不能绕过工具
注册表调用未授权工作流。

## 观测与验收

运行详情至少显示当前节点、每个节点状态、尝试次数、开始结束时间、触发来源和错误码。AI 节点还要
显示选择的是员工还是模型，以及启动时实际模型配置。普通日志不记录完整提示词、知识正文或 Key。

验收从正式页面拖入节点、连接、配置、保存并启动；然后验证 SSE 增量、刷新恢复、停止、失败重试和
最终摘要。直接调用编译器只算分层测试。员工触发还要从真实会话让模型调用工具，并确认同一运行在
工作流详情可追溯。
