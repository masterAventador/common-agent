# 通用 Agent 中台第一版产品范围

> 状态：已确认的 MVP 基线  
> 确认日期：2026-07-19  
> 核心原则：会话优先、单链路、先看到真实回复

## 1. 产品定位

`common-agent` 是通用 AI 中台，第一版提供 AI 会话、数字员工、知识库和可视化工作流。Skill 属于后续能力，不进入当前 MVP。

`automation-tool` 是独立的业务自动化产品，负责 RPA、内容生产、社交运营等具体业务。两个项目可以未来通过稳定 API 协作，但当前不共享业务代码、不相互导入，也不把业务自动化重新包装成中台能力包。

旧 `agent-platform` 只作为架构和规则参考，不作为当前项目的交付范围。

## 2. 核心交互模型

产品必须像普通 AI 聊天工具一样工作：

1. 用户选择一个数字员工并进入会话；
2. 用户发送一条消息；
3. 数字员工在同一个会话中流式回复；
4. 用户继续追问，上下文保持在当前会话；
5. 数字员工可以绑定一个知识库，每次提问自动检索；工作流保持独立，只有确实触发时才形成一次工作流执行。

内部可以为一轮回复创建 `turn_id` 或生成轨迹，但这些只是实现细节。普通对话不得跳转到任务中心，不要求用户启动、审批或管理任务。

工作流是独立能力：它有自己的定义、输入、输出和运行记录。用户可以从工作流入口手动触发；数字员工也可以在得到允许时，通过同一个公开工作流服务触发。数字员工不能内嵌、复制或拥有工作流实现。

## 3. 第一版纵向闭环

第一版先完成核心会话纵向场景：

```text
打开聊天工作台
  -> 选择“知识助理”数字员工
  -> 新建或打开会话
  -> 发送一个问题
  -> KnowledgeService 自动从员工绑定的 RAGFlow 知识库检索上下文
  -> Deep Agents 生成回答
  -> 同一会话流式显示回复与知识引用
  -> 用户继续追问并得到下一轮回答
```

另有一条独立工作流闭环：用户把节点卡片拖入画布并连接成“开始 → 处理节点 → 结束”，保存后从开始节点运行并看到每个节点的流转与最终结果；随后数字员工可通过受控工具调用同一个已保存工作流，并把结果以会话消息或内联卡片返回。

真实外部服务未配置时，系统可以使用确定性的 Demo Adapter 跑通相同 UI、API 和事件协议，但界面必须明确显示“演示模式”。只有真实 RAGFlow、模型和 Deep Agents 链路验收通过后，相关任务才能标记 `✅ 已完成`。

## 4. MVP 功能清单

### 4.1 AI 会话

- 左侧显示会话列表；
- 新建会话并选择数字员工；
- 中间区域显示用户和数字员工消息；
- 支持流式文本、停止生成、失败重试和继续追问；
- 助手消息可展示引用来源和简洁的执行状态；
- 会话和消息持久保存，刷新后可以继续查看历史并追问。

### 4.2 数字员工

- 提供一个预置的“知识助理”，同时支持最小创建和编辑；
- 数字员工定义包含名称、说明、系统指令、一个可选知识库绑定和允许调用的工作流 ID；
- 支持列表、创建、编辑、选择知识库和用于新会话；
- 第一版不做头像上传、发布、版本、权限、复制和市场。

### 4.3 工作流

- 提供独立的可视化工作流设计器；
- 左侧节点面板可以把卡片拖到画布，画布节点可以连线和删除；
- 第一版节点类型固定为：开始、AI 对话、知识检索、结束；
- 工作流拥有独立定义、输入 Schema、输出 Schema 和运行状态；
- 保存前必须校验唯一开始节点、至少一个结束节点、开始到结束可达、无孤立节点、连线合法、节点类型和配置有效；
- 后端把通过校验的节点图转换为 LangGraph，按连线从开始节点执行到结束节点；
- 运行时展示当前节点、已完成节点、失败节点和最终输出；
- 用户可以在工作流页面填写输入并手动触发；
- 数字员工可以通过受控工具调用同一个 `WorkflowService`，不得绕过服务直接导入工作流图；
- 工作流定义和运行摘要持久保存；
- 第一版不做条件分支、循环、并行、子流程、审批、断点恢复、定时执行、版本发布和多人协作。

### 4.4 知识库

- 通过 `KnowledgeService` 接入独立 RAGFlow；
- 支持列表、创建知识库、上传文档和查看解析状态；
- 数字员工可以绑定一个知识库；没有绑定时正常对话但不执行检索；
- 每条用户消息先自动检索绑定知识库，再把相关片段交给数字员工；
- 回复展示可追溯的引用标题和片段；
- 第一版不做复杂切片配置、批量迁移、权限、标签、图谱和 RAGFlow 运维页面。

### 4.5 运行状态

- 工作台显示后端、模型、RAGFlow 和当前运行模式；
- 缺少配置时给出明确、可操作的错误；
- 不展示伪造的“全部正常”状态。

## 5. 明确不做

第一版禁止进入以下范围：

- 注册、登录、用户、组织、租户、RBAC 和 SSO；
- 任务中心、任务调度、定时任务、审批和审计中心；
- 面向用户的模型网关、成本、配额、计费、供应商路由和多模型管理；当前产品只暴露阿里百炼配置；
- Skill 管理、数字员工和知识库的高级管理后台，以及工作流的版本、发布、权限和运行运维后台；
- 长期记忆、文件空间、沙箱、MCP 市场和插件市场；
- 当前 MVP 不做 Tauri/Electron 等桌面壳、移动 App、行业能力包和客户解决方案包；桌面 App 自动更新仅作为 Q6-05 之后的独立任务，不得提前进入当前纵向闭环；
- RPA、视频、内容生产、社交运营和其他 `automation-tool` 业务；
- 远程部署、生产高可用、监控大盘和云资源采购；当前全部在本机联调。

这些是用户可见产品功能的范围边界，不是技术方案白名单或禁用清单。任何数据库、中间件、存储、运行时、协议、调度、观测和工程工具，包括但不限于 PostgreSQL、Redis、消息队列、对象存储与 Worker，都可以在服务当前闭环、可靠性、并发、可维护性或演进需要时进入工程架构和路线图，不需要被包装成新的产品功能；是否采用以及如何验收由架构文档和路线图负责。

新增用户功能只有在 MVP 纵向闭环完成后才能进入路线图；“以后可能需要”不是提前扩展业务范围的理由。

## 6. MVP 完成定义

第一版只有同时满足以下条件才算完成：

- 本机可分别启动前端和后端，浏览器打开后直接进入聊天工作台；
- 不经过登录即可新建会话并与“知识助理”连续对话两轮；
- 每条用户消息都在当前会话中得到对应助手回复，不创建用户可见任务；
- 可以创建知识库、上传文档并看到真实解析状态；
- 可以创建或编辑数字员工并绑定一个知识库；
- 每次向已绑定知识库的员工提问都会自动检索，并在回复中展示引用；
- 用户可以从独立工作流设计器拖拽并连接“开始 → AI 对话或知识检索 → 结束”，保存后手动运行并查看节点流转和结果；
- 数字员工可以通过受控工具触发同一个工作流服务，只有此时才在会话中显示工作流执行卡片；
- Demo 模式的前后端、协议和核心 Playwright 链路完整通过；
- 本机 RAGFlow 检索、Deep Agents 执行、阿里百炼回复和引用展示完成一次真实验收；
- 外部服务未配置或失败时，界面显示真实错误且可重试；
- 后端 pytest/Ruff/Mypy、前端 Vitest/ESLint/Typecheck/Build 和核心 Playwright 全部通过；
- `docs/development-roadmap.md` 记录每项任务的状态和实际证据；
- 验证结束后停止本轮启动的前后端服务，不遗留测试进程和临时资源。

## 7. MVP 之后的顺序

纵向闭环完成后按真实反馈决定，不预先承诺全部实现：

1. 会话持久化与历史记录；
2. Skill、数字员工和知识库高级管理，以及工作流分支、循环、版本和发布；
3. 文件上传、长期记忆、工具/MCP 和沙箱；
4. 多用户、登录、组织、权限和审计；
5. 配额、面向用户的多模型管理、运行治理和生产部署。

每一阶段仍以一个可用用户闭环为单位拆分，禁止再次把所有平台能力放进同一首期。

## 8. 已登记的 MVP 后任务

### 8.1 桌面 App 自动更新

完成 Web MVP 之后可以建立桌面 App 正式分发与自动更新。更新能力必须封装为与中台业务
零耦合的独立通用模块，由不同 App 注入应用标识、版本源、签名、轮询和提示界面，能够直接
复用于 `automation-tool`；版本清单和安装包由用户自己的服务器提供。实现时优先复用与最终
桌面壳匹配的成熟更新 SDK，没有满足策略、兼容性和维护性要求的成熟方案时再自研底层流程。

App 启动时及后台周期轮询正式版本清单，发现新版本后先下载到本地，新包以原子替换覆盖旧
下载包。可选更新向用户提供：

- 立即安装：退出主 App，再交给正式安装器完成安装；
- 暂不安装：本次继续使用，但以后每次启动或轮询到该版本时继续询问；
- 跳过此版本：持久化跳过当前版本，仅检测到更高版本时重新下载并询问。

强制更新没有跳过或暂缓选项：后台下载完成后，下次启动在进入主 App 前直接执行安装。
更新包必须验证版本、签名和哈希；下载中断、磁盘不足、替换失败、安装失败和重启循环必须
有明确恢复路径。具体状态和实施证据只在 `docs/development-roadmap.md` 的 `U7-01` 维护。
