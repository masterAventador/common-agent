# 企业知识库产品边界

> 状态：独立企业知识库产品的功能与范围边界
> 建立日期：2026-07-28
> 核心原则：会话优先、单链路、先看到真实回复
>
> 本文件只定义产品功能和范围边界，不记录任务进度。任务顺序、状态、验证证据和遗留只维护在
> `docs/development-roadmap-v3.md`。本文件只在产品功能或范围边界真实变化时更新，普通开发
> 任务完成不得为了同步状态修改它。

## 1. 产品定位

`common-agent` 是企业知识库产品。用户把企业文档汇入知识库，通过 AI 会话和数字员工检索、
提问并得到带引用的回答；工作流提供可视化的多步骤编排；工具与 MCP 让数字员工在获得显式
授权后调用外部能力。

产品围绕「问企业自己的资料」这一条主线建设。任何新增能力都必须能说清它如何服务这条主线，
否则不进入范围。

## 2. 核心交互模型

产品必须像普通 AI 聊天工具一样工作：

1. 用户直接进入通用 AI 会话，或选择一个数字员工进入员工会话；
2. 用户选择当前可用模型并发送一条消息，系统在首次发送时原子创建会话；
3. 通用 AI 或数字员工在同一个会话中流式回复；
4. 用户继续追问，上下文保持在当前会话；
5. 数字员工可以绑定一个知识库，每次提问自动检索；工作流保持独立，只有确实触发时才形成一次
   工作流执行；
6. 用户可以为通用会话或数字员工显式选择当前可用工具能力，模型只有在本轮确实需要时才经统一
   MCP 出口调用，界面展示安全的工具执行状态后继续回复。

内部可以为一轮回复创建 `turn_id` 或生成轨迹，但这些只是实现细节。普通对话不得跳转到任务
中心，不要求用户启动、审批或管理任务。

工作流是独立能力：它有自己的定义、输入、输出和运行记录。用户可以从工作流入口手动触发；
数字员工也可以在得到允许时，通过同一个公开工作流服务触发。数字员工不能内嵌、复制或拥有
工作流实现。

## 3. 功能边界

### 3.1 AI 会话

- 左侧显示通用与数字员工历史会话；
- 点击 AI 会话直接进入空白通用对话，不要求数字员工或提前创建会话；
- 首次发送在正式入口内原子创建会话、用户消息、助手占位和回复任务，失败时不保留空会话；
- 输入区只列当前工作区用户已创建且启用的模型，并允许每轮发送前切换；
- 通用会话保存当前模型选择；员工会话默认使用员工模型，临时切换只影响发送轮次且不改员工定义；
- 支持流式文本、停止生成、失败重试和继续追问；
- 支持从业务工具集或单项能力中显式选择工具；通用会话保存精确能力列表，默认不授予任何工具；
- 助手消息可展示引用来源和简洁的执行状态；
- 会话和消息持久保存，刷新后可以继续查看历史并追问。

### 3.2 数字员工

- 提供一个预置的"知识助理"，同时支持最小创建和编辑；
- 数字员工定义包含名称、说明、系统指令、当前工作区模型配置中的一个默认模型、一个可选知识库
  绑定、允许调用的工作流 ID、业务工具集选择和精确工具能力授权；
- 选择整个工具集只展开保存当时已有的能力；工具集或 MCP 后续新增能力不会自动进入既有员工；
- 支持列表、创建、编辑、选择知识库和用于新会话；
- 不做头像上传、发布、版本、权限、复制和市场。

### 3.3 知识库

- 通过 `KnowledgeService` 接入独立 RAGFlow；
- 每个平台工作区使用一个独立 RAGFlow 技术账号/租户；工作区成员共享该技术身份，不共享其他
  工作区的 Token 或知识库命名空间；
- 创建工作区时自动初始化对应 RAGFlow 账号、API Token 和平台规定的 embedding/rerank 模型。
  默认工作区升级时原位接管既有账号和知识库，不复制数据；无法安全归属的旧非默认映射关闭失败；
- 支持列表、创建知识库、上传文档和查看解析状态；
- 文档解析覆盖正文、表格与图片；配置视觉模型后，图片由模型生成可检索的文字描述；
- 文档内嵌的多媒体（PDF 的 `/EmbeddedFiles`、`/Screen`、`/RichMedia`，Office 的 `media/`
  与 OLE 嵌入对象）属于知识库解析范围。内嵌音视频经视觉/多模态模型转成可检索文本，必须有
  大小与数量闸门，且解析失败不得静默丢弃、要给用户可见提示；
- 数字员工可以绑定一个知识库；没有绑定时正常对话但不执行检索；
- 每条用户消息先自动检索绑定知识库，再把相关片段交给数字员工；
- 回复展示可追溯的引用标题和片段；
- 不做复杂切片配置、批量迁移、权限、标签、图谱和 RAGFlow 运维页面。

### 3.4 工作流

- 提供独立的可视化工作流设计器；
- 左侧节点面板可以把卡片拖到画布，画布节点可以连线和删除；
- 节点类型固定为：开始、AI 对话、知识检索、结束；
- 工作流拥有独立定义、输入 Schema、输出 Schema 和运行状态；
- 保存前必须校验唯一开始节点、至少一个结束节点、开始到结束可达、无孤立节点、连线合法、
  节点类型和配置有效；
- 后端把通过校验的节点图转换为 LangGraph，按连线从开始节点执行到结束节点；
- 运行时展示当前节点、已完成节点、失败节点和最终输出；
- 用户可以在工作流页面填写输入并手动触发；
- 数字员工可以通过受控工具调用同一个 `WorkflowService`，不得绕过服务直接导入工作流图；
- 工作流定义和运行摘要持久保存；
- 不做条件分支、循环、并行、子流程、审批、断点恢复、定时执行、版本发布和多人协作。

### 3.5 运行状态

- 缺少配置时给出明确、可操作的错误；
- 不展示伪造的"全部正常"状态。

### 3.6 数据生命周期

- 用户可以从正式平台入口删除会话、数字员工、知识库和工作流；
- 删除会话会级联清理消息、引用和由该会话触发的工作流运行；正在生成回复时拒绝删除；
- 删除数字员工前必须先删除引用它的会话；删除知识库前必须先解除员工绑定并修改引用它的工作流
  节点；
- 删除工作流前必须先从员工允许列表解除绑定，并等待活跃运行完成或停止；已终止运行随定义删除；
- 四类删除都支持安全重试：资源已经不存在时仍视为成功；RAGFlow 删除结果不确定时不伪装成功，
  页面保留当前快照并提示刷新状态后重试。

### 3.7 大列表管理

- 会话、数字员工、知识库、工作流和会话内运行摘要统一返回 `items + next_cursor`，支持服务端
  搜索和每页 `1-100` 条的有界读取；游标只用于同一资源、搜索词和页大小，条件改变后必须从
  第一页重新开始；
- 平台 MySQL 资源按不可变的 `created_at DESC, id DESC` 做 keyset 分页；知识库仍只通过
  RAGFlow 官方数据集列表 API，页码差异封装在适配层，不泄漏给平台和前端；
- 页面保留当前搜索条件和已加载页，按 ID 去重；创建或删除后废弃旧页链并从第一页读取权威状态，
  以免并发新增、删除造成重复或遗漏；
- 只提供名称/标题/输入的索引前缀搜索，以及完整稳定 ID、运行状态搜索；不引入高级筛选、标签、
  批量操作或分析报表。

### 3.8 身份边界

- 空数据库允许通过一次性引导令牌创建且只能创建一名首位所有者；
- 所有业务入口要求登录，支持安全注销、会话过期和恢复码重置密码；
- 浏览器看不到服务端会话令牌，写请求必须通过 CSRF 与可信来源校验；
- 首位所有者自动拥有默认组织和默认工作区，可以在同一组织创建其他工作区；
- Owner 可以创建 Editor/Viewer 成员账号并一次性取得其恢复码；Owner/Editor 可读写业务资源，
  Viewer 只读，只有 Owner 可管理工作区和成员；
- 员工、会话、工作流和运行按工作区隔离；知识库同时受 RAGFlow 原生租户和平台归属复核两层
  约束，跨租户 REST、SSE、检索和工具调用统一拒绝；
- 不提供公开注册、邮件邀请、成员删除/转移、角色自定义、细粒度授权或 SSO。

### 3.9 审计与安全事件

- 登录、注销、恢复凭据、成员创建、工作区创建、配置/绑定变更、上传、删除、会话回复、工作流
  运行/停止，以及认证、权限和限流拒绝都写入审计；员工通过工具触发工作流也不能绕过；
- Owner 可以查询当前工作区审计或平台级认证/安全事件，并按操作者、动作、资源与时间过滤，
  Viewer/Editor 不可访问；
- 审计只记录固定动作、结果、请求/追踪 ID、可选操作者/资源/稳定错误码与时间，不记录请求正文、
  密码、Token、恢复码、提示词、知识正文或任意扩展元数据；
- 工作区与平台各自使用单调序号和 SHA-256 哈希链；数据库拒绝修改或删除已有事件，Owner 可从
  页面校验链完整性；
- 默认保留 365 天、每个作用域最多 1,000,000 条，不自动清理；容量耗尽时受审计的成功写请求
  关闭失败，不能静默丢失证据。保留期仅标记策略边界，后续删除必须经过独立合规流程。

### 3.10 用户模型配置

- 当前工作区可以维护自己的阿里百炼聊天模型配置，只包含显示名称、百炼模型标识和启用状态；
- 百炼 API Key、Base URL、超时和重试仍由平台服务端统一管理，不返回前端，也不允许用户覆盖；
- 模型管理页只展示用户已经创建的配置，不枚举或伪造百炼全部模型目录；
- 用户可以从正式页面测试指定模型，调用必须经过平台 API 和百炼正式适配器；
- 模型配置按工作区隔离，停用配置不再进入新的业务选择器，已存在引用继续保留；数字员工、工作流
  或会话仍引用时拒绝删除；
- 数字员工创建和编辑从当前工作区已启用模型中选择默认模型；模型停用后既有员工继续保留并使用
  原绑定，但新员工和模型切换不能再选择该配置；
- 通用会话与每条助手消息分别持久化当前选择和实际调用模型；员工会话仍以员工当前默认模型作为
  每次重新进入时的初始值，单轮临时切换不得反向修改员工配置；
- 只支持单一百炼提供商，不提供供应商路由、成本、配额、计费或通用模型网关。

### 3.11 工具与 MCP

- 提供工具箱入口，管理平台托管 MCP、外部 MCP、业务工具集和当前可用能力；Owner/Editor 可写，
  Viewer 只读；
- 平台托管 MCP 用一个业务 Base URL 归组同域 HTTP 接口；每个接口是一项能力，可配置 method、
  path、说明、参数名称/含义/类型/位置、超时和可选响应提取；
- 支持手工维护能力，也支持导入受限 OpenAPI 3 JSON/YAML，先预览、选择和补充说明，再原子批量
  导入；
- 一个业务工具集可以关联多个平台托管或外部 Streamable HTTP MCP；能力目录统一展示来源与状态，
  数字员工不需要知道背后是内部 HTTP 还是第三方 MCP；
- 平台实际授权和调用都落到稳定的单项能力 ID。集合是管理与选择视图，不是动态继承权限；新增、
  改名、停用、同步或删除能力不得静默改写既有授权；
- 通用 AI 和数字员工都通过 Deep Agents 调用工具。唯一内置工具是零费用、无外部依赖的"当前
  时间"，且仍需显式授权；
- 工具调用过程使用稳定调用 ID，在会话中显示开始、完成或失败；凭据、完整请求/响应正文默认不
  展示、不进入审计，外部副作用结果不确定时不自动重试；
- 托管 HTTP 鉴权只支持无认证、Bearer Token 和自定义 Header。用户名/密码代登录、OAuth、
  任意本机 stdio MCP、工具/MCP 市场和付费内置工具不进入范围；
- 平台维护模型工具流兼容性。经真实调用证明无法稳定关联流式 tool-call chunk 的模型，在绑定
  工具时自动改用供应商非流式调用；浏览器仍通过平台 SSE 得到状态和最终回复。

### 3.12 RAGFlow 集成

- RAGFlow 仍是知识数据和索引权威，平台继续只通过 `KnowledgeService` 和公开 API 访问；
- 允许维护基于官方精确提交的私有补丁版 RAGFlow，目标限于可复现的性能、正确性问题，以及本文件
  已纳入范围但上游未提供的解析能力；
- 私有补丁必须进入私有 GitHub 仓库和 common-agent submodule 锁定提交，不使用运行中容器热改、
  未提交工作树或本机旁路源码。

## 4. 明确不做

当前仍禁止进入以下范围：

- 公开成员注册、邮件邀请、成员删除/转移、自定义角色、细粒度资源授权和 SSO；
- 任务中心、任务调度、定时任务和审批；
- 面向用户的模型网关、成本、配额、计费、供应商路由和多提供商管理；当前只允许维护阿里百炼
  聊天模型配置，平台仍统一保管供应商凭据；
- Skill 管理、数字员工和知识库的高级管理后台，以及工作流的版本、发布、权限和运行运维后台；
- 长期记忆、文件空间、沙箱、MCP/插件市场、任意本机 stdio MCP 和付费内置工具；
- Tauri/Electron 等桌面壳、移动 App、行业能力包和客户解决方案包；
- RPA、社交运营、营销内容生产等与企业知识库主线无关的业务自动化能力；
- 生产高可用、监控大盘和云资源采购。

这些是用户可见产品功能的范围边界，不是技术方案白名单或禁用清单。任何数据库、中间件、存储、
运行时、协议、调度、观测和工程工具，包括但不限于 PostgreSQL、Redis、消息队列、对象存储与
Worker，都可以在服务当前闭环、可靠性、并发、可维护性或演进需要时进入工程架构和路线图，
不需要被包装成新的产品功能；是否采用以及如何验收由架构文档和路线图负责。

## 5. 新增功能进入范围的规则

- 新增用户功能必须先说明它如何服务「问企业自己的资料」这条主线；说不清的不进入范围；
- 「以后可能需要」不是提前扩展业务范围的理由；
- 新增功能只有在既有纵向闭环完成后才进入路线图，且以一个可用用户闭环为单位拆分，禁止把多项
  平台能力塞进同一批次；
- 边界真实变化时在同一个任务内更新本文件，不允许实现先行、文档后补。
