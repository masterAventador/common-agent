# 通用 Agent 中台前端架构

> 状态：V1 已落地，V2 工具箱与会话工具交互目标已确认
> 确认日期：2026-07-22
> 技术栈：React + TypeScript + Vite + Ant Design

## 1. 产品界面

V2 完成后，认证业务区有七个真实入口，其中审计入口只对 Owner 可见：

```text
/chat                 AI 会话
/employees            数字员工
/knowledge-bases      知识库
/workflows            工作流
/model-configurations 模型管理
/tools                工具箱
/audit-events         审计事件（仅 Owner）
```

应用根部由 `AuthGate` 控制：空数据库显示首位所有者创建页，已有所有者但没有有效会话时显示
登录/恢复页；只有认证成功后才挂载业务入口并把根路径转到 `/chat`。没有任务中心、仪表盘、
设置中心或其他空菜单。

有效会话恢复后，`AuthProvider` 必须先取得当前账号的工作区列表并选定一个工作区，随后才挂载
业务路由。顶部选择器显示工作区与 Owner/Editor/Viewer 角色；Owner 可以创建同组织工作区和
添加成员，Viewer 看到只读提示，所有业务写入口禁用，但后端 RBAC 仍是最终权限边界。

## 2. 技术决策

- React + TypeScript + Vite；
- Ant Design 作为通用组件体系；聊天消息可使用 Ant Design X，但只有确认它能降低维护成本时才引入；
- React Router 管理七个入口，并在路由与导航两层隐藏非 Owner 的审计页；工具箱只有在对应后端
  能力交付后才加入，不建立占位页面；
- Axios 负责普通 HTTP 与文件上传；
- TanStack Query 管理模型配置、员工、知识库、会话、消息和工作流快照；
- Zod 在 API 边界校验后端响应；
- 原生 `EventSource` 或受控 SSE 客户端携带 Cookie 接收会话和工作流事件；
- `@xyflow/react` 负责画布拖拽、缩放、节点和连线；前端不自研图形交互内核；
- Zustand 暂不引入，除非工作流编辑草稿跨组件状态无法由局部 reducer 清晰表达。

## 3. 页面结构

### 3.0 身份入口

- 首位所有者表单要求邮箱、强密码和一次性引导令牌，成功后只显示一次恢复码；
- 登录表单只提交邮箱和密码，不暴露账号枚举信息；恢复入口消费一枚恢复码并设置新密码；
- 会话 Cookie 为 `HttpOnly`，JavaScript 不读取或保存会话令牌；CSRF 令牌只存在当前 React
  内存中，刷新页面时通过已认证的会话接口重新取得；
- 注销调用后端撤销会话后再清空 Query；任何接口收到 `401` 都关闭业务区并回到登录页。
- 当前工作区 ID 不是凭据；API 客户端在内存中维护它，并可按用户在 localStorage 记住最后选择，
  但会话 Cookie、CSRF、密码、恢复码和引导令牌都不得随它持久化；
- 普通业务请求统一携带 `X-Tenant-ID`。会话和工作流原生 EventSource URL 只附加已验证的
  `tenant_id`，同时继续使用同源 HttpOnly Cookie；切换工作区时清空 Query Cache，禁止复用上一个
  工作区的快照或流式状态。

### 3.1 AI 会话

桌面端采用三栏结构：

```text
会话列表 | 消息与输入区 | 当前数字员工/知识库信息
```

- 左栏：主菜单下方的分隔线、通用/员工历史会话和当前选择；
- 中栏：用户/数字员工消息、流式文本、引用、停止和重试；
- 右栏：通用 AI 的本会话工具授权，或员工名称、说明、绑定知识库、允许的工作流和继承的工具数量；
- 点击 AI 会话进入空白通用对话；选择员工仅用于员工对话，不是新会话的前置条件；
- 空白对话不先调用创建 API，首次发送经原子首轮入口建立会话并提交回复，失败不留下空会话；
- 输入区模型选择器只展示当前工作区用户创建且启用的配置，并在每轮请求中显式提交所选配置；
- 输入区或右侧能力面板只展示当前工作区可用的业务工具集和单项能力；通用会话默认不选工具，
  首次发送把授权快照与首轮消息原子保存，后续修改经独立保存动作落库；不把集合当成动态权限，
  既有但暂不可用的能力可原样保留或显式撤权，不能借编辑新增不可用能力；
- 通用会话恢复持久化模型；员工会话每次重新进入时以员工当前默认模型初始化，页面内临时切换
  不修改员工定义；
- 普通消息永远留在会话页，不跳转任务详情；
- 员工确实触发工作流时，在助手消息中显示可展开的运行卡片。

移动窄屏不是第一版正式交付目标，但页面不得完全不可用；侧栏可收起为抽屉。

### 3.2 数字员工

- 列表展示名称、说明和绑定知识库；
- 创建/编辑表单包含名称、说明、系统指令、默认模型、知识库、允许工作流、业务工具集和单项能力；
  选择整个工具集只展开当时叶子能力，页面保存前展示实际授权数量和来源；默认模型只列当前
  工作区已启用配置，编辑时允许原样保留当前已停用绑定但不能重新选择；
- 员工卡片显示默认模型名称和停用状态，模型列表读取失败时表单关闭失败并提供重试；
- 保存后可直接“与该员工对话”；
- 不显示发布、版本、权限、市场等未实现操作。

### 3.3 知识库

- 列表展示 RAGFlow 的真实知识库和文档/解析状态；
- 支持创建知识库；
- 支持上传文档并显示上传、解析中、完成、失败；
- 解析状态来自后端/RAGFlow，不使用前端计时器伪造完成；
- 第一版不复制 RAGFlow 的全部高级配置界面。

### 3.4 工作流

```text
节点面板 | 可缩放画布 | 节点配置/运行结果
```

- 节点面板：开始、AI 对话、知识检索、结束；
- 拖入画布后生成稳定节点 ID；
- 节点之间通过 Handles 连线；
- 右侧面板编辑节点配置；
- 保存时先做即时客户端提示，再以服务端校验为最终结论；
- 点击运行后展示当前节点、完成/失败状态和最终输出；
- 前端只编辑 JSON 图，不执行节点或推导真实运行顺序。

### 3.5 审计事件

- Owner 可在工作区与平台作用域间切换，并按操作者、动作、资源类型/ID、起止时间查询；
- 页面展示序号、时间、结果、操作者、资源、稳定错误码、请求/追踪 ID 和哈希摘要，不展示或请求
  业务正文与凭据；
- 保留天数、作用域容量和“不自动删除”策略始终可见；完整性入口展示哈希链是否通过以及断点；
- 列表使用后端游标继续加载，切换作用域或过滤条件时废弃旧页；Editor/Viewer 即使手工访问 URL
  也由前端路由和后端 RBAC 双重拒绝。

### 3.6 模型管理

- 页面只展示当前工作区用户创建的百炼模型配置，不加载供应商完整模型目录；
- 创建/编辑表单维护显示名称、百炼模型标识和启用状态，不请求或展示 API Key、Base URL；
- 卡片展示平台按模型标识派生的工具调用流兼容状态；该状态没有表单开关，租户不能自行登记或取消；
- “测试调用”始终经正式平台 API 使用服务端凭据访问该配置指定的百炼模型，并展示安全结果或稳定错误；
- 删除使用统一二次确认；存在数字员工、工作流或会话引用时保留卡片并提示先解除引用；
- 列表使用服务端游标、前缀搜索和刷新后的 MySQL 权威状态，Viewer 只读。

### 3.7 工具箱

- 工具箱提供托管 HTTP MCP 来源、鉴权、手工能力、OpenAPI 导入、发现、外部 Streamable HTTP
  MCP 显式同步、业务工具集和带副作用警示的测试调用；员工编辑页与通用会话右栏复用严格目录契约
  保存精确授权，Viewer 只能查看，不能修改；
- 页面分为 MCP 来源、业务工具集和能力目录三类真实视图，不复制 RAGFlow 或第三方 MCP 的管理 UI；
- 平台托管 MCP 支持 Base URL、无认证/Bearer/自定义 Header、能力手工维护和 OpenAPI 文件导入；
  凭据字段只显示固定掩码，编辑时留空表示保留原值，任何响应和 Query Cache 都不能出现明文；
- 外部 MCP 首期只接 Streamable HTTP URL 与受控 Header，显式“同步能力”后逐来源展示待同步、可用
  或连接异常；Schema 漂移能力显示待确认并禁止调用，不在保存表单时用假成功代替真实发现；
- 业务工具集可以关联多个 MCP 来源。能力树按工具集 → MCP 来源 → 单项能力展示，父节点勾选只在
  当前交互展开到叶子 ID，后续远端同步不自动改变员工或会话授权；
- OpenAPI 导入上传 `.json/.yaml/.yml` 后先展示规范化预览、既有名称和递归缺失说明；既有能力默认
  不勾选，用户可逐项选择并编辑名称、说明、输入 Schema、参数映射、响应 Pointer 和超时，再一次
  提交原子导入。浏览器只做 5 MiB 预检与严格响应解析，不解析规范正文、不直连业务 Base URL；
- Viewer 可查看目录和状态但不能新增、编辑、刷新、导入或删除；Owner/Editor 的写操作继续经过
  CSRF、可信 Origin、租户隔离和统一确认交互。

## 4. 前端目录和依赖方向

```text
src/app
  -> src/features/*
       -> src/api
       -> src/schemas
       -> src/components（仅真实跨 Feature 复用）
```

- Feature 之间不直接导入内部组件、hooks 或状态；
- `ChatPage` 与 `WorkflowsPage` 只处理页面级加载/错误和区域编排；Query、Mutation、SSE、URL
  同步与运行协调分别进入 `useChatPageController` / `useWorkflowDesigner`；
- 聊天消息投影、消息/引用展示和三栏工作区分别由 `chatState`、`ChatMessages`、
  `ChatWorkspace` 承担；全局分页历史、归属、选中和删除状态由 `ConversationHistory` 承担；工作流
  节点面板、画布、属性/运行面板与拖拽协议分别独立；
- Feature 实现不得反向导入页面容器；跨 Feature 只能依赖对方公开 `index`，拆分模块不得形成
  循环依赖；这些约束由后端架构测试扫描前端源码；
- API 客户端是访问后端的唯一入口；
- Axios 统一启用 credentials，并只为认证后的非安全方法注入当前内存 CSRF；EventSource 同样
  显式启用 credentials，不通过 URL、localStorage 或响应可见字段传递身份令牌；
- 认证和 `/tenants` 列表/创建请求不依赖已选择租户；其余业务 REST 由统一客户端注入租户头，
  SSE 因浏览器原生 EventSource 不能设置自定义头而使用租户查询参数；
- 生成 DTO 位于 `src/api/generated/`，禁止手工修改；
- Zod Schema 可以把生成 DTO 转成更适合页面使用的视图模型；
- 常量与错误文案集中定义，避免多个页面维护不同状态词汇。

## 5. 服务端状态和流式状态

### 5.1 快照权威

模型配置、员工、知识库、工具目录/授权、会话、消息和工作流列表均由 TanStack Query 快照管理。
SSE 只更新当前流式投影；
客户端用最后确认的事件序号跨 API/Worker 重启续传，事件已超过服务端保留期、序号缺口或未知版本
时重新获取 MySQL 权威快照。

### 5.2 列表搜索与游标状态

模型配置、会话、员工、知识库、工作流和运行摘要使用 `useInfiniteQuery` 保存搜索词对应的独立页链；API 层
统一解析 `items + next_cursor`，页面只把后端返回的游标传回，不解释其内容。合并页时按稳定 ID
去重，加载下一页期间保留已有数据；搜索词改变后使用新的 Query Key 从第一页开始。

创建或删除成功后使用 `resetQueries` 废弃受影响列表的全部旧游标页，再从第一页获取权威排序；
失败时保留原快照。远程选择器同样使用服务端搜索和按需加载，不再为了下拉框先取得完整员工、
知识库或工作流集合。页面的“加载更多”只在 `next_cursor` 存在时启用，避免重复请求末页。

### 5.3 会话 reducer

会话事件只允许：

- 把助手消息从 `pending` 推进到 `streaming`；
- 按序追加 delta；
- 更新检索状态和引用；
- 进入 `completed`、`failed` 或 `stopped` 终态。

工具调用事件按同一会话序号处理 `tool.started/tool.completed/tool.failed`，使用稳定 `tool_call_id`
关联并只展示能力名称和安全状态；重复、倒序、未知工具事件或终态后事件触发快照校正，不在浏览器
保存完整参数、结果或认证信息。

晚到事件、重复事件和终态后的 delta 必须忽略并触发必要的快照校正。

### 5.4 工作流编辑状态

工作流草稿使用单一 reducer 维护：

- `nodes`；
- `edges`；
- 当前选择节点；
- 未保存标记；
- 服务端校验错误；
- 当前运行投影。

不能把节点位置、业务配置和运行状态混在同一个不可控对象中。

## 6. 错误与状态展示

- 顶部状态区显示后端、百炼和 RAGFlow 的真实状态；
- 缺少配置、服务不可达、上传失败和工作流非法都给出明确操作建议；
- API Key、第三方响应体和内部路径不得进入通知详情；
- 会话 Cookie、密码、恢复码和引导令牌不得进入日志、Query Cache、URL、持久化存储或错误详情；
- 加载、空数据、失败和成功状态都有独立展示；
- Demo/Test Adapter 必须显示演示标记，不能与真实集成状态混淆。

### 6.1 资源删除交互

- 会话、员工、知识库和工作流的删除入口都显示资源名称及不可恢复影响，并要求二次确认；
- 不做乐观删除：后端返回 `204` 后才失效对应详情、列表、消息或运行 Query，并把当前选择安全
  移到仍存在的资源或空状态；失败时保留原快照；
- 引用阻断错误转换为可操作说明，分别引导先删除会话、解除员工知识库/工作流绑定、修改工作流
  知识节点，或等待/停止活跃运行；
- RAGFlow 删除结果不确定时提示刷新列表确认，不在前端自动重放外部删除；
- U9-02 的浏览器门禁必须从页面完成创建、建立引用、观察阻断、解除引用、删除与刷新消失。

## 7. 可访问性与交互

- 表单字段有可见标签和错误关联；
- 消息输入支持键盘发送与换行；
- 停止生成和重试按钮有明确可访问名称；
- 工作流画布提供节点列表/属性面板作为键盘可操作补充；
- 颜色不作为节点状态的唯一提示；
- 四类资源删除必须确认并提供清晰目标、影响范围、阻断原因和失败后的保留状态；确认弹窗和结果
  通知具备键盘焦点与明确可访问名称。

## 8. 测试门禁

### Vitest + Testing Library

- 数字员工表单和知识库绑定；
- 通用空白会话首次发送、员工/通用模型初始化和逐轮模型切换；
- 会话 reducer 的有序、重复、缺口、终态和重试；
- 文档上传与解析状态；
- 工作流节点拖入、连线、配置和服务端校验错误映射；
- API/Zod 边界和安全错误展示。
- 模型配置创建、编辑、停用、真实测试调用、引用删除阻断和只读状态。
- MCP 来源/能力/工具集管理、凭据掩码保留、OpenAPI 预览导入、精确授权和新增能力不自动扩权。
- 工具事件有序投影、失败/断流恢复，以及流式不兼容模型最终回复不丢失。
- 身份门禁、首位所有者、登录/恢复、注销、会话失效和 CSRF 注入。
- 工作区恢复/切换、Owner 创建工作区和成员、Viewer 只读入口与租户请求注入。
- Owner 审计菜单/路由、作用域与过滤器、游标加载、保留策略、哈希链完整性和非 Owner 拒绝。

### Playwright

核心流程必须覆盖：

1. 首位所有者注册、恢复、登录、注销、过期/撤销与 Cookie 重放失败；
2. 缺失 CSRF、跨源注册和跨源写请求关闭失败；
3. 创建知识库并上传测试文档；
4. 创建数字员工并绑定知识库；
5. 与员工连续对话两轮并看到引用；
6. 创建“开始 → 知识检索或 AI 对话 → 结束”工作流；
7. 手动运行工作流并看到节点流转和结果；
8. 让数字员工触发允许的工作流并在会话中看到运行卡片；
9. 后端、RAGFlow 或模型不可用时显示真实错误并可恢复。
10. Owner 创建受审计资源后从页面按资源过滤命中事件，并验证链完整性、保留策略和正文/凭据不出现。
11. 从模型管理页面创建、真实调用百炼、刷新、编辑停用，并验证引用阻断和解除引用后的删除。
12. 直接进入通用 AI 空白页，首次发送原子创建会话，以两个已创建模型逐轮真实调用百炼，并在
    刷新后恢复通用会话模型；员工临时切模后重新进入仍恢复员工默认模型。
13. 创建托管 HTTP MCP 与业务工具集，从通用会话和数字员工分别显式授权并调用“当前时间”及一个
    真实测试 HTTP 能力；新增另一项危险能力后，刷新证明既有授权没有自动增加。
14. 导入 OpenAPI、接入隔离外部 MCP、验证工具事件/刷新恢复，并让已登记的不兼容模型在工具调用时
    自动使用供应商非流式路径得到正确结果。

Playwright 使用项目专属或随机空闲端口，结束后停止 Vite、FastAPI 和浏览器进程。

## 9. 构建边界

- 当前只构建本机 Web 资产，不部署服务器；
- 七个页面继续使用独立动态 import；Vite 8 通过 `build.rolldownOptions.output.codeSplitting`
  把 React、Ant Design、数据客户端和工作流画布依赖拆成带内容哈希的稳定 vendor 组，并按入口
  感知使用关系，且启用严格执行顺序避免拆分后的共享模块循环改变副作用初始化顺序；不能用手工
  合并把未使用的工作流画布塞进其他页面；
- 生产构建必须生成 manifest 并通过 `check-bundle-budget.mjs`：所有初始/异步 JS chunk 不超过
  500,000 bytes，任一页面首次静态 JS 依赖图不超过 1,500,000 bytes，七个页面必须仍是异步入口；
  `pnpm build` 自带该门禁，不得通过提高 Vite warning 阈值或跳过分析放行；
- 生产 preview 的无头浏览器逐个直达七入口并完成菜单切换；第二轮菜单切换不得再次请求已加载
  JS，页面错误和 10 秒本机首屏上限任一失败都会关闭失败；
- Vite 默认绑定 `127.0.0.1` 和项目专属端口；
- `.env.example` 只包含后端 Base URL 等非敏感配置；
- 百炼和 RAGFlow Key 不进入任何 `VITE_*` 变量；
- 构建产物、测试报告、截图和 Trace 不进入 Git。
