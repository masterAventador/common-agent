## 1. 背景与现状

## 2. 产品边界（每个任务都必须守）

- 只复用 demo 的**布局骨架、交互结构、视觉语言**；
- **不照搬** PowerAI 名称、电力行业定位、示例账号/数据、供应商目录（PowerAI Pro/Flash 等）；
- **不引入** demo 的"团队空间""执行监控""技能库""设置"页，以及卡片上的"团队可见性/负责人"
  等团队协作字段——这些超出当前产品范围（我们是工作区 + Owner/Editor/Viewer RBAC）；
- demo 没有、我们特有的页面（工具与 MCP、审计与安全事件）：不照搬 demo（它没有），按 DESIGN.md
  的同一套设计语言与已对齐的其他页保持一致；
- 业务文案、功能、路由、数据契约继续以本项目为准，不因对齐视觉而改动。

### UI-00 全局色调基线（2026-07-25 完成）

- 用无头浏览器渲染 demo 原型并读取 computed style，实测其画布 `#F5F2EB`、卡片 `#FBFAF5`、
  侧栏 `#EFEBE1`、边框 `#E2DCCD`，**比 DESIGN.md 原色值表（`#FAFAFA`/`#FFFFFF`/`#EDEDE9`）明显更暖**。
  DESIGN.md 的文字描述本就是 "warm off-white / paper-calm"，色值偏冷属文档自身不一致。
  **用户确认取暖米一版**，已同步修订 DESIGN.md 色值表与 Quick reference。
- 同时查清「上次 UI 改造没效果」的真正原因：`index.css` 里有 **139 处硬编码旧色**（`#315efb`
  鲜蓝 19 处、蓝紫渐变、冷蓝灰边框与浅底几十处），而 `4c796b0` 只是**在文件末尾追加覆盖规则**，
  旧规则一行未删。于是 token 改了页面却不跟着变，且同一选择器存在两套打架定义。
  本次已把它们收敛到 token：硬编码 139 → 40（余下为 `:root` 定义本身、DESIGN.md 规定的
  tag palette、深底白字），`var(--*)` 引用 81 → 179，并删除 `.entry-shell` / `.knowledge-page` /
  `.employees-page` 三处被完全覆盖的死规则。

### UI-01 设计决策（已确认）

> **2026-07-25 变更：侧栏不再改窄。** 用户实际体验后判断 demo 的 64px 纯图标 rail「不方便」，
> 决定**保持现有宽侧栏（232px，图标 + 文字标签）**。据此 **UI-01a（窄 rail）与 UI-01c（历史会话
> 迁移）整体作废**——历史会话继续留在侧栏，不再搬进对话页。DESIGN.md 的 sidebar 表述已同步改为
> 232px 并写明为何不采用原型的窄 rail。这一变更同时消除了本路线图风险最高的一步（全局壳层重写）。
> 下方原始决策记录保留以备追溯。

- **历史会话方案**：核实 demo 对话页**没有历史会话列表**（源码里的"今天"是文档更新时间/运行时间，非对话历史；demo 对话页是纯单栏）。我们的历史会话是核心功能不能丢，因此定为 **窄图标 rail（所有页）+ 历史会话迁到对话页内的历史栏**（ChatGPT/Claude 式，符合会话优先定位，视觉按 DESIGN.md）。历史迁移由 UI-01c 承接，避免中途功能回归。

### 待跟进：工作流路由首屏被画布库拖大（UI-10 期间发现）

`workflowEditor.ts` 静态导入了 `@xyflow/react` 的 `addEdge` / `applyNodeChanges` /
`applyEdgeChanges` 三个运行时函数，而它又被 `WorkflowSidebar` 与 `useWorkflowDesigner` 静态
引用，导致**整个画布库被算进 /workflows 首屏图，尽管画布组件本身已经 lazy 加载**。这让该路由
长期贴着门禁上限（余量一度只剩 5694 字节），任何新增依赖都会立刻爆掉。

侧边栏其实只需要 `WORKFLOW_NODE_LABELS` 常量，并不需要画布库。合理修法是把这三个函数的调用
移出 reducer、由已在 lazy 边界内的画布层算好结果再 dispatch，预计可为该路由省出约 170KB。
属 UI 范围外的架构改造，未在本次顺手动手，单独跟进。

UI-00 与 UI-01~UI-09 **已全部完成**并通过真实页面验收，分支 `ui-align-demo`（4 次提交已推送）。
final gate 已跑通：前端 166 测试 + eslint + typecheck + 构建包体预算，后端 926 测试 + Ruff + Mypy。

剩余动作：等用户确认视觉后合并回 `main`（按规范用 `git merge --no-ff`）。

后续若再对齐原型，执行每一页前先用无头浏览器打开 demo 对应页读取真实 computed style 再动手，
不要凭截图目测色值——UI-00 就是靠这一步才发现 DESIGN.md 色值与原型不一致。

### 与原型的已知差异（有意保留）

- **侧栏宽度**：用户明确否决原型的 64px 窄 rail，保持 232px 宽导航（沿用 UI-01 决策）。
- **知识库页**：原型该页其实是**文档**卡片墙，没有"多个知识库"的概念；本项目是知识库 → 文档
  两级，保留左右两栏（知识库列表 + 文档与解析状态），文档卡片本身已按 `.ktile` 对齐。
- **思考过程折叠块**：原型有 `.think` 折叠块，但平台的 `MessageResponse` 没有推理内容字段，
  后端也不产出。没有真实数据就不做这个 UI，避免用假内容冒充已接通能力。
- **AI 回复的"用时"**：原型显示"用时 6.2s"是写死的示例。平台的 `created_at`/`updated_at` 在
  重试后会把用户的思考间隔算进去，据此推时长不可信，因此署名行右侧显示的是消息时间而非时长。
- **标题衬线字体**：原型标题用 Newsreader（Google Fonts）。中文没有对应字形会回落到系统黑体，
  实际只影响拉丁文标题；为不引入 CDN 字体依赖未照搬。
- **模型表格的供应商/上下文/能力筛选**：原型是"模型网关"形态，这些字段本项目没有对应数据。
